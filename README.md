# MultiCodeAttack

Short description

MultiCodeAttack is an experimental framework for studying query-based attacks (jailbreak / prompt-based attacks) and defense mechanisms against large language models (LLMs). The codebase supports both natural-language (text) and code-generation tasks, implements template-driven attack pipelines, automated variant generation via LLMs, bandit-based template selection, self-judging and victim-model evaluation, and hyperparameter ablation experiments.

Highlights

- Template variant generation (`generate_variants`) using LLMs to produce semantically equivalent prompts/templates.
- Bandit-based macro-structure selection (`UCB1Bandit`) for exploring/exploiting template families.
- Adaptive thresholding (`AdaptiveThreshold`) to decide which variants are promoted to persistent pools.
- Multiple baseline defense implementations for controlled comparisons.


## Project Structure

This project mainly contains the following Python files:

- `translator.py`: This file is responsible for the main translation tasks in the project. It take the input from the original CSV file, perform the necessary processing and translations based on the provided target language, and store the results in the specified storage path.
- `trans_llms*.py`: Perform automated content analysis on an input sentence using an LLM and extract three short, cleaned fields for downstream template filling or safety evaluation.
- `evaluate_responses.py`: This file is used to assess the harmfulness of responses generated by MultiCodeAttack for harmful text generation task.
- `evaluate_responses.py`: This file is used to assess the harmfulness of responses generated by MultiCodeAttack for harmful text generation task.
- `text2code*.py`: The files are specific to the malicious code generation including attack, evaluation, and concrete templates.
- `adaptive_test.py`: The attack algorithm for text generation task.
- `*log`: store the detailed attack logs.
- `*response`: store the attack results of each baseline.
- `*test`: store the final evaluation results of each baseline.


## Minimal environment and installation

1. Python: 3.9 or newer.
2. Create a virtual environment and install dependencies:
   ```sh
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

## Configuration

- `openai_log.py` reads credentials and endpoint settings from environment variables. Set `PRIMARY_API_KEY` and `PRIMARY_BASE_URL` for the main model. Set `SECONDARY_API_KEY` and `SECONDARY_BASE_URL` if using the secondary model. Model names default to `gpt-4o` and `gpt-3.5-turbo`; override them with `PRIMARY_MODEL` and `SECONDARY_MODEL`.
- Keep API credentials in your shell environment; do not put them in source files or commit them.

Example for the current shell (replace the value with your own key):

```sh
export PRIMARY_API_KEY="your-api-key"
export PRIMARY_BASE_URL="https://api.openai.com/v1"
```


## How to run

- Run a single text-task experiment:
  python adaptive_test.py --store_path data

- Run a single code-task experiment:
  python text2code_adapvetest.py --store_path data


## Important implementation notes

- To ensure hyperparameter changes take effect, calls to `generate_variants` explicitly pass `k=VARIANTS_PER_ROUND`. If you modify constants at runtime, confirm scripts pass parameters down to called functions.
- `openai_log.py` contains many hard-coded example API keys and local host URLs; replace them with your valid credentials or secure them in environment variables before running experiments in production.
